# How Much I Get From Codex

**[English](README.md) · [中文](README.zh-CN.md)**

一个挂在 Codex 分析页上的油猴面板，算出 OpenAI 不公布的那个数：**你的订阅到底给了你多少 API 用量。**

官方页面只给一根进度条——*Monthly usage limit，还剩 70%*。70% 的什么？分母从来没在任何地方出现过。这个脚本把它从接口里读出来。

![](docs/panel.jpg)

<sub>跟随浏览器的浅色 / 深色主题。</sub>

给 Plus、Pro、Business、Team 用户里那些用 Codex 用到会想「这订阅到底值多少」的人。

**不点开就不发请求。** 不轮询，页面加载时不发，关掉之后也不留东西在跑。

---

## 它告诉你什么

- 一份额度值多少钱，你已经用掉几份
- 当前窗口还剩多少，按你的速度什么时候用完
- 到订阅续费之前还会开出多少
- 一个 turn 多少钱，一千行代码多少钱
- 哪一天、哪个模型、哪个入口花得最多

---

## 额度是怎么读出来的

两个接口各拿着一半答案：

| 接口 | 给什么 | 缺什么 |
|---|---|---|
| `daily-workspace-usage-counts` | 每天花了多少 credits | 一份额度是多少 |
| `usage/daily-token-usage-breakdown` | 每天**占一份额度的百分之几** | 具体金额 |

一除就是 1% 值多少：

```
额度 = 某天的 credits ÷ 那天的百分比 × 100
```

在一个真实 Plus 账号上，这个比值**在有用量的 26 天里全部等于 49.897，离散度是 0**——额度 4,989.7 credits。其中有一天正好落在 100.000%，所以这个数也可以直接读出来，连除法都不用。

**一天数据就够，而且全程不碰限流窗口。** 这很关键，因为窗口不总是真的：有些套餐上 `used_percent` 永远是 0，`reset_at` 跟着当前时间往前滑。拿花费去除它，会得到一个建立在空气上的笃定数字。脚本会识别这种窗口，把所有依赖它的东西藏起来。

两路信号同时存在时，每日比值负责给出额度，实时窗口除法只做交叉校验。两者相差超过 5%，面板保留每日实测值，并把两个数字都写出来，不会悄悄换来源。

这也顺手解决了「下次什么时候重置」——**办法是不问**。每天的百分比就是那天吃掉了一份额度的多少，加起来就是用掉几份，过 100% 就是又用掉一份。

### credits 从哪来

个人套餐接口直接给 credits，**接口给的永远优先**。不计 credits 的套餐会报 0，这时候脚本才用 [Codex 官方 rate card](https://learn.chatgpt.com/docs/pricing) 自己按 token 算；下表核对日期是 **2026-08-10**。

| 模型 | 未缓存输入 | 缓存输入 | 输出 |
|---|---|---|---|
| gpt-5.6-sol | 125 | 12.5 | 750 |
| gpt-5.6-terra | 50 | 5 | 300 |
| gpt-5.6-luna | 5 | 0.5 | 30 |
| gpt-5.5 | 125 | 12.5 | 750 |
| gpt-5.4 | 62.5 | 6.25 | 375 |
| gpt-5.4-mini | 18.75 | 1.875 | 113 |
| gpt-image-2（text tokens） | 125 | 31.25 | 250 |

单位是 credits / 1M tokens。分析接口给的是 text token 字段，所以 GPT-Image-2 用 text 那一行，不拿 image token rate 代替。已从当前表移除的模型另放在 legacy 表里，历史记录不会消失；实际用到时面板会标出来。

Fast mode 另算当前公布的倍率——GPT-5.6 和 5.5 是 **2.5×**，GPT-5.4 是 **2×**（[来源](https://learn.chatgpt.com/docs/agent-configuration/speed)）——脚本读 `speed` 字段，两档分开计价。标准 / fast 两行之间按花费份额拆 turns，跟界面写的规则一致。

模型没有 rate 时，不会凭空给它的 token 定价。已知模型加起来与接口当日总额之间的差，会进「未归因」，这样模型合计始终能跟大字对上。

### 换成美元

界面按 **1 credit = $0.04** 换算，这个数来自 credit 购买页。OpenAI 没公布统一的 credit / 美元汇率，所以它是写明白、可以改的显示假设，不属于 rate card。你的账号价格不一样，就改脚本顶部的 `USD_PER_CREDIT`。

所以美元数的含义就是 **credits × 配置的显示汇率**。它不是 OpenAI 的成本，也不是这份额度的售价。

## 什么时候它拒绝回答

给一个笃定的错数，比空着更糟。所以只要脚下的地基塌了，面板就不给数：

- **窗口不到一天。** 用量只按整个 UTC 天上报，五小时的窗口没有可除的东西。不给额度，不给周期视图。
- **窗口根本没开。** 0% 已用 + 重置时间一直往前滑，这是占位符。实测的额度和花费照常显示，周期边界和据此数出来的东西全部隐藏。
- **额度中途变过。** 这时候「N 个窗口 × 今天的额度」会高估这笔订阅费买到的量——翻倍的情况下虚高 43%。份数照给，乘出来的那个数不给。
- **Fast mode 没有公布倍率。** 按标准价计并标注偏低，而不是把邻近模型的倍率安到它头上。
- **rate card 里没有的模型。** token 不计价；接口报出的 credits 差额留在「未归因」里。
- **同结构订阅不止一份。** 两个 workspace seat 或两份 personal 订阅都可能是当前 Codex 上下文时，无法证明哪个续费日才对。面板让你选一次续费日；选定前不给账期数字，也不会拿自然月顶上。

### 前瞻

开出一份额度有两个途径：窗口按自己的时钟滚动，以及**手动用掉一张重置券**提前开一份。两者都读得到——`reset_at` 是固定边界往后一步步数，`rate_limit_reset_credits.available_count` 说明还剩几张券——所以前瞻是算出来的，不是对未来的猜测。

**花钱是按窗口封顶的，不是按天。** 第一个早上就把一份额度烧完，那个窗口剩下的时间跑多快都拿不到东西。所以拿日均往后推，会推出账号根本达不到的总数。现在的推算被「续费前实际会开出几份额度」封顶，面板还会告诉你是哪个约束在起作用。

## 已知的偏差，以及各自的方向

这些不是未知数，是**方向已知**的偏差，看数的时候心里有数就行。

| 来源 | 方向 |
|---|---|
| **额度池是共享的。** Codex、ChatGPT Work、ChatGPT for Excel 吃同一份额度，但这个接口只看得到 Codex | 花费偏低，额度跟着偏低 |
| **周期边界和天对不齐。** 窗口按时间戳开始，用量按整个 UTC 天分桶，而且 `group_by=hour` 被拒绝 | 开窗那天会多算，周期花费偏高。真发生时面板会标出来 |
| **窗口百分比精度粗**——接口只给到整数位 | 只影响兜底路径，也就是拿不到每日百分比的时候 |

有两件事接口根本不提供：

- **单次 turn 的花费。** 最细只到「天 × 模型 × 速度」，所以面板给的是「单 turn 最贵的**那一天**」和「单 turn 最贵的**那个模型**」。
- **按仓库的花费。** `code-attribution` 只接受 `group=workspace`，其他分组一律拒绝，分不出项目。能拿到的最接近的维度是**入口**——CLI、VS Code、网页、GitHub。

### 你看的是哪份订阅

一个登录可以同时挂着 personal 的 Plus 和 workspace 的席位。Codex 的接口回答的是 Codex 自己所处的上下文，**它跟档案菜单里显示的账号常常不是同一个**——加 `ChatGPT-Account-ID` 头也覆盖不掉。所以面板抬头会写明套餐和账号邮箱。personal + workspace 可以按结构区分；同一种结构下有多份有效订阅时，面板会判为歧义，在能确定 seat 之前也不会写入按 seat 分桶的本地历史。如果接口把 `account_id` 留空，续费日选择会按邮箱和套餐存在本浏览器里，也能在订阅视图里更改。

所有请求都带 `workspace_user=true`，数字只覆盖当前 seat。

## 安装

1. 装 [Tampermonkey](https://www.tampermonkey.net/)
2. 点 **[how-much-i-get-from-codex.user.js](https://github.com/bigbobro/how-much-i-get-from-codex/raw/main/how-much-i-get-from-codex.user.js)**，Tampermonkey 会自己接住
3. 打开 <https://chatgpt.com/codex/cloud/settings/analytics>，点右上角那个标签

更新走 `@updateURL` 指回这个仓库，所以往这里推一次，装过的人都能收到。

界面语言跟随浏览器，也可以在面板里切。

`@match` 是在页面加载时生效的，所以从设置侧边栏点进 Analytics 不会出现触发器——刷新一次就有了。

## 开发

`smoketest.html` 把录下来的真实接口响应喂给脚本，不联网、不用登录：

```bash
python3 -m http.server 8731
```

打开 `http://127.0.0.1:8731/smoketest.html?all=1` 会跑完所有确定性断言。测试会冻结时钟、给 userscript 加 cachebuster、核对固定 7 次请求、拦住 userscript console error，并逐场景打印 PASS / FAIL。

| 场景 | 覆盖什么 |
|---|---|
| *（默认）* | 窗口百分比兜底、账期来源标签、视图 / 语言切换焦点，以及关闭 / Escape / 背景关闭后的焦点恢复 |
| `#personal` | Plus 型：workspace 接口 400，额度实测 **$199.59** |
| `#spill` | 账期在一个取不全的窗口中间开始——账期内那截花费必须以「跨期」截断行出现，窗口表合计必须等于大字 **$209.57** |
| `#currentspill` | 当前窗口跨过账期起点——当前行与合计都只计期内的 **$149.90** |
| `#multi` | 7 天窗口，一个跑完的周期，多份额度前瞻 |
| `#boundary` | 窗口在 06:00 UTC 开——分段必须精确切分那些天 |
| `#changed` | 额度中途翻倍，读数跟到今天并说明剔掉了几天 |
| `#conflict` | 每日实测 **$399.18** 胜过冲突的窗口推算 **$299.39**，两个数都要交代 |
| `#unknownmodel` | 未知模型把接口报出的 **$49.90** 对进「未归因」，不能出现 NaN 或零元模型行 |
| `#mixedunknown` | 已知模型保留自己的 **$0.20**，只有接口总额剩下的 **$1.80** 进「未归因」 |
| `#bank` | 还剩重置券，要加在自然滚动的窗口之上 |
| `#unusedcard` | 状态 `unused` 不能被误判成 `used` |
| `#twosubs` | 一个登录两份订阅——面板必须写明报的是哪一份 |
| `#sameworkspaces` | 两份同结构 workspace 订阅——先选续费日，选定前不写按 seat 分桶的历史 |
| `#samepersonals` | 两份同结构 personal 订阅——选 08/18 后重新拉取并统计真实的 07/18 → 08/18 账期 |
| `#hourly` | 5 小时窗口——拒绝推算并说明原因 |
| `#fresh` | 占位符窗口 |
| `#fast` | 标准 / fast 的 turns 都按花费份额拆；没公布的倍率继续标注 |
| `#noent` | 拿不到续费日期——不给订阅账期数字，也不拿自然月代替 |
| `#zerobasis` | 最近一个完整窗口花费为 0 时，0 仍是有效节奏基准 |
| `#rates` | 当前 Terra、Luna、GPT-Image-2 text token rate |
| `#projection` | 占位符保留实测花费与自然日日均，但不给无上限外推 |

默认场景仍要复现录下来的 **花费 $249.83 / 额度 $250.00**。整套测试还会统一检查 `NaN` / `undefined`，并确认窗口表合计跟账期大字对得上。

测试桩**故意**按 `start_date` / `end_date` 过滤。不过滤的话，一个场景可能会用脚本根本没取到的数据「通过」测试——取数不足的 bug 就是这么在绿灯下活下来的。
